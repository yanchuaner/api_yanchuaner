# 安全基线

## 上线门槛

- 一年运营资格、品牌使用范围、修改权、源码义务和到期处置方式已归档。
- OpenAI 与 DeepSeek 的授权明确覆盖认证校友代理访问、公益额度和计划中的收费方式。
- 公网只开放 HTTPS 反向代理；数据库、Redis、LiteLLM 管理端和 pprof 不对公网监听。
- New API 关闭密码登录、密码注册、充值、支付、邀请、兑换码和未批准模型；总注册开关仅为主站 OAuth 首次建号保留。
- 只有 `yanchuaner` OAuth 提供方可把主站 `admin` 同步为 root；普通成员和其他提供方不能通过自定义字段提权。
- 完成授权码重放、账号停用、Token 撤销、超额并发、上游超时和账单退款测试。

## 密钥

- 开发、测试、生产使用完全不同的密钥和数据库。
- `NEW_API_CRYPTO_SECRET`、`LITELLM_SALT_KEY` 一旦用于加密数据，不得在无迁移方案时直接轮换。
- LiteLLM master key 只用于本地管理，不作为 New API 的长期渠道 Key。
- 上游真实密钥只通过受控管理界面或密钥管理系统注入，不写入 Git、Compose、命令历史和工单。
- 所有可撤销 Key 都必须记录所有者、用途、模型范围、预算、速率限制、创建与撤销时间。
- 启用 `YANCHUANER_HASHED_KEYS_ENABLED` 后的新虚拟 Key 只在创建响应显示一次；数据库哈希、前缀和尾号不得被当作 bearer credential。
- 启用 `YANCHUANER_QUOTA_LEDGER_ENABLED` 后，已迁移公益额度路径禁止绕过流水直接修改余额。旧业务入口保持关闭，直至完成迁移。
- `YANCHUANER_VIRTUAL_KEY_POLICY_ENABLED` 默认关闭。启用前必须审查回填禁用清单并验证 Redis；启用后缺失/禁用策略或 Redis 后端故障必须拒绝请求，活动策略不得使用通配供应商。
- 部署自动化 root 管理令牌只保存在被 Git 忽略的 `deploy/.env`，不得展示在网页、日志或文档示例中。

## 请求与日志

- 默认不记录完整提示词、响应正文、Authorization、Cookie 和供应商请求头。
- 用户日志展示和管理员日志严格分级；导出前再次脱敏。
- 统一限制请求体、上下文长度、每 Key 并发/RPM/TPM、单次最大费用和月度总预算；多副本环境不得依赖进程内限流。
- 禁止任意 Base URL；允许列表必须阻断回环、内网、链路本地、云元数据地址和 DNS 重绑定。

## 事件处置

发生密钥泄露、异常费用或越权时，顺序为：暂停对应渠道，撤销下游虚拟 Key，轮换上游密钥，冻结受影响用户 Token，保全脱敏审计日志，核对供应商账单，再恢复最小模型集合。

Open WebUI `0.10.2` 的品牌变更受其许可证最终用户数量、书面许可或企业许可条件限制。授权证据未归档时，不得扩大到超过许可证例外范围的预览用户。
