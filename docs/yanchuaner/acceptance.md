# 内测验收矩阵

## 阶段 A：基础设施

| 场景 | 通过标准 |
| --- | --- |
| Compose 解析 | 不依赖 `latest`，所有必填密钥缺失时直接失败 |
| 网络暴露 | PostgreSQL、Redis 不发布端口；New API 与 LiteLLM 仅监听 `127.0.0.1` |
| 重启 | 容器重启后用户、渠道、额度和日志数据保持一致 |
| 备份恢复 | 两个 PostgreSQL、Redis 和必要配置可在隔离环境恢复 |

## 阶段 B：身份

2026-07-21 的 WSL 隔离证据已覆盖主站提供方 45 项 HTTP 合同，包括登录、`access_denied`、精确回调、S256 PKCE、一次性授权码、错误客户端、UserInfo、RS256/JWKS 和 `iss` / `aud` / `nonce`。这不代表 New API 或 Open WebUI 消费者回调已经通过。

| 场景 | 通过标准 |
| --- | --- |
| 未登录访问 | 回到主站登录页，登录后恢复原授权请求 |
| 非认证账号 | 回调 `access_denied`，New API 不创建用户 |
| 本地密码 | 登录与注册接口均拒绝，登录页只显示主站 SSO |
| 认证成员 | 已认证在校生、校友与教师创建唯一 OAuth 绑定，重复登录复用同一 New API 用户 |
| 主站管理员 | 仅受信任的 `yanchuaner` OAuth 角色可同步 root 权限；其他提供方不能提权 |
| 回调篡改 | 非精确 `redirect_uri` 被拒绝，不发生跳转 |
| 授权码重放 | 首次换取成功，第二次返回 `invalid_grant` |
| 错误客户端密钥 | 返回 `invalid_client`，日志不包含密钥、授权码或 Token 正文 |
| 主站账号停用 | 新授权立即失败；存量 New API Token 的同步停用机制上线前另行验收 |
| OIDC 发现 | 宿主机和容器均可读取发现文档，且只声明 RS256 ID Token 签名 |
| JWKS | 至少发布一个 RSA 公钥，不包含私钥参数 |
| AI 登录 | Open WebUI 关闭本地注册，仅通过主站 OIDC 为认证校友自动建号 |
| 临时账号 | 两条回调验收完成后删除主站、New API 和 Open WebUI 的临时账号 |

## 阶段 C：公益额度

| 场景 | 通过标准 |
| --- | --- |
| 新用户 | 首期仅获得 `$1.00 / ¥7.00`，不能绕过模型组与额度上限 |
| 初始流水 | OAuth 用户创建、绑定和 `grant` 流水同事务提交；失败时三者均回滚 |
| 虚拟 Key | 新 Key 只显示一次；数据库只保存 SHA-256 派生值，哈希本身不能重放 |
| 旧 Key 轮换 | 盘点全部明文 Token，逐个新建、验证、撤销；没有“原地自动哈希” |
| AI 工作台 | 共享服务 Token 有限额，重复执行部署脚本不会重置已消费余额 |
| 自主 AI 会话 | 主站登录只返回一次 15 分钟应用 Key；库内仅哈希；旧会话失效；未配置模型或预算时拒绝签发 |
| 发放 | 管理员必须填写原因；金额、目标用户、操作者和原因可追溯 |
| 正常请求 | New API 预扣与结算差额正确，LiteLLM 只做成本核对 |
| 幂等 | 同一请求和阶段重试不重复扣费，复用幂等键但改变金额时拒绝 |
| 流水查询 | 登录用户只能分页读取自己的流水，request ID 可关联用量日志 |
| 上游失败 | 未产生有效消费时退回预扣，日志保留请求关联标识 |
| 并发耗尽 | 并发请求不能把余额扣成负数 |
| 虚拟 Key 策略 | 开关开启后缺失/禁用策略拒绝；活动策略只允许 OpenAI/DeepSeek 且必须覆盖模型白名单；每次更新要求原因并追加版本修订 |
| 每 Key 限流 | 标准文本请求按 Key 执行 RPM、提示加最大输出 TPM 预留和并发限制；真实用量结算，失败退回 TPM；Redis 已配置但故障时返回 503 |
| 策略兼容投影 | Token 的模型、来源 IP、有限预算和有效期仍生效；任一层拒绝均不得进入上游或静默扩大权限 |
| 策略原子编辑 | 用户端一次提交同时更新策略和 Token 兼容投影并追加含模型、来源、预算、有效期与状态的完整修订；任一校验或写入失败全部回滚；旧 Token 更新接口返回 409 |
| 历史 Key 回填 | 启动不自动写入；管理员先读取不含 Key 的预检报告，再以明确 Token ID 和原因执行最多 100 项原子批次；无法安全分类的项保持禁用并冻结仍启用的旧 Key |
| 协议边界 | 受策略管理 Key 只允许已纳入预留和结算的同步文本协议；媒体、Realtime、Embedding 和异步 Task 在专项实现前返回 403 |
| 对账 | New API 用户账本总额与 LiteLLM、供应商账单差异在解释范围内 |

## 阶段 C-P1：活动权益

| 场景 | 通过标准 |
| --- | --- |
| 独立存储 | 活动、兑换码、权益、领取和权益流水使用 YanCore 独立表，不写入 New API `Redemption` |
| 兑换码保密 | 创建响应只显示一次明文；数据库、查询和审计不得返回摘要原文 |
| 来源分账 | 活动领取总账 `funding_source=campaign`，与 `public_benefit`、BYOK 不静默互相扣减 |
| 幂等领取 | 同一用户/活动重复请求返回原权益；不重复增加用户余额、不重复写授予流水 |
| 上限并发 | 活动和兑换码领取上限在事务锁下生效；超过上限返回冲突且不产生权益 |
| 回滚 | 任一权益、领取或总账写入失败，全部事务回滚 |
| 活动消费 | 开启 `YANCHUANER_CAMPAIGN_FUNDING_ENABLED` 后，匹配供应商/模型的活动权益先预扣；`RelayInfo.BillingSource=campaign` 可关联用量日志 |
| 结算退款 | 活动请求的实际消耗差额和失败退款只更新活动权益与 `campaign` 总账，不增加 `public_benefit` 流水 |
| 不足隔离 | 匹配活动权益不足时请求拒绝，不静默改扣公益余额；无匹配活动时钱包只可使用公益/兼容旧余额，活动额度不得被越权扣减 |
| 异步门禁 | 当前异步任务尚未持久化 `entitlement_id`；匹配到活动权益时明确拒绝，不允许静默降级到钱包 |

## 阶段 D：BYOK（第二阶段）

进入本阶段前，A-C 必须全部通过。BYOK 验收至少包括密钥增加、连通性测试、轮换、撤销、删除、备份不可读、管理员不可见明文、日志无泄露、公益额度与 BYOK 资金来源明确且不静默切换。

## 上线判定

任何一项身份绕过、负余额、密钥明文、账单无法解释或回滚失败均为阻断项。RC 版本至少连续运行 7 天并完成一次故障和恢复演练后，才可进入小范围认证校友试运行。
