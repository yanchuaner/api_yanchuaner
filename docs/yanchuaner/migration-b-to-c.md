# B 到 C 分阶段迁移清单

执行顺序固定为：先冻结需求、接口、依赖与许可边界，再完成设计、实现、迁移和验证。依赖升级必须独立提交并遵守 `dependency-baseline.md`，不得与业务替换混合。

## P0：可审计预览闭环

### 工作项

- 主站唯一 OAuth/OIDC 身份和角色白名单。
- 哈希虚拟 Key，一次性展示，旧明文 Key 轮换。
- 公益额度不可变流水、管理员理由、请求 ID 关联。
- OpenAI/DeepSeek 标准文本模型最小集合。
- 生产迁移、并发耗尽、失败退款、备份恢复和许可证门禁。

### 验收

- 三类认证成员和管理员角色测试通过，未认证/停用账号拒绝。
- `$1 / ¥7` 初始赠额、创建 Key、真实调用、结算/退款和审计可逐请求对账。
- 数据库秘密扫描找不到虚拟 Key 明文，上游 Key 不出现在日志或前端。
- Open WebUI 品牌授权证据归档，或强制不超过许可证阈值并恢复必要品牌。
- PostgreSQL/Redis 不暴露公网，恢复演练达到约定 RPO/RTO。

### 回滚

- 冻结新 Key 和模型调用，保留登录与只读账单。
- 回滚到固定镜像，保留新增列/表；按最后流水 ID 核对后恢复。
- 上游异常先停渠道、撤销内部 Key，再轮换供应商 Key。

## P1：自主权益与密钥域

当前已完成的 P1 slice：

- `YanCoreCampaign`、`YanCoreRedeemCode`、`YanCoreEntitlement`、`YanCoreEntitlementClaim` 和权益流水为独立自主表，不复用 New API `Redemption`。
- 管理员可创建有效期、额度、供应商/模型范围和领取上限，兑换码只保存 SHA-256 摘要并只在创建响应展示一次。
- 用户领取在单事务内锁定活动和兑换码，写入权益领取记录、权益流水和 `campaign` 来源总账；同一用户/活动重复领取为幂等返回，余额不重复增加。
- 模型测试覆盖首次领取、重复请求、来源分账和领取上限；尚未开放真实生产活动、定向人群规则和消费时的多来源扣减。

### 工作项

- 独立 entitlement、campaign、redeem_code、claim 和目标人群模型。
- 每 Key provider/model allowlist、RPM、TPM、并发、预算、有效期和来源。
- 公益、活动、班级/年级权益完全分账，明确扣减顺序，不自动跨来源。
- BYOK Vault/Broker：信封加密、KMS/KEK、所有者绑定、脱敏运维和密钥轮换。
- Open WebUI 用户级委托，消除共享服务 Key 的个人归因缺口。
- outbox/consumer 将账本、调用审计和成本对账可靠关联。

### 验收

- 每种资金来源独立余额和流水，任一来源耗尽不会扣另一来源。
- 兑换并发、重复提交、过期、目标人群和领取次数测试通过。
- 管理员无法通过日常 API 读取 BYOK 明文；日志、追踪、备份秘密扫描通过。
- 每 Key 限流在 Redis 故障时按明确 fail-open/fail-closed 策略工作。

### 回滚

- 活动和 BYOK 均有独立总开关；关闭后不删除密文或流水。
- 双写期 New API 仍为兼容读面，差异超过阈值自动停止切流。
- KEK 轮换失败回退旧版本引用，不覆盖唯一密文。

## P2：自主控制面与客户端

### 工作项

- 将身份映射、虚拟 Key、权益、审计、风控和管理 API 移出 New API 进程。
- New API/LiteLLM 只作为协议网关，通过短效内部凭据调用。
- 自主用户端和管理端替换上游业务 UI；Open WebUI 降为可替换客户端。
- 数据双写、回放校验、灰度流量、全量切换和旧模块只读下线。

### 验收

- 核心业务仓库有独立 LICENSE、SECURITY、CONTRIBUTING、数据字典、迁移和威胁模型。
- 连续两个账期双写差异为零，故障演练和容量测试通过。
- 关闭 New API 核心业务模块后，身份、Key、权益、调用和审计闭环仍完整。

### 回滚

- 按租户/用户哈希灰度，支持分钟级路由回旧控制面。
- 切换期间旧库只读保留，达到保留期和审计签字后才下线。
- 不复制上游具体实现；兼容性以公开协议、黑盒契约测试和自主设计为证据。
